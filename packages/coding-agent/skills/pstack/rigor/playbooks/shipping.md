### Shipping

**You own what lands. Verify each PR independently, land only the verified run from the root, then keep your hands off the stack.**

1. **Verify each PR independently before it lands.** One verifier per PR, a child agent that did not write the code, runs the change the way a user would on the real surface (`bash` with tmux for CLIs and TUIs, a browser MCP server for web UIs), parent against head, and returns `PASS`, `PASS+NOTES` or `FAIL`. Spawn it with `rlm.spawn` on `model=state["models"]["judgment"]` and a `contract` with a check that the verdict's head matches. Trust a verdict only when `check["outcome"] == "verified"`. Green CI and an approving bot review are not verdicts, because neither runs the change as a user would.
2. **Land only the contiguous verified run rooted at the bottom.** Walk up from the lowest unmerged PR and stop at the first one without `PASS` or `PASS+NOTES`. A verified PR above an unverified one waits, because it cannot land without the code below it.
3. **Re-check that the verdicts still describe the code.** A chain rebase moves every PR above it to a new SHA without failing any check. Compare `git patch-id` at the verdict SHA with the current head before trusting an older verdict. When the patches differ only in tests, docs or lint config, the lane's result stands if what it ran builds the same at both SHAs. Report each kind of noise with its files. The change itself still gets fresh checks and a review.
4. **Land bottom-up, one PR at a time.** Merge the run's lowest unmerged PR with `gh pr merge <pr> --squash`. A PR whose base is still its parent's branch merges into that branch, not trunk. Read the PR back with `gh pr view <pr> --json state,mergedAt,baseRefName`, because a requested auto-merge is not a merge. After a merge lands, retarget the PR whose base was the merged branch to trunk (`gh pr edit <pr> --base <trunk>`), move its patch onto the merge result, and push with `--force-with-lease`. Arm auto-merge only on a PR whose verdict covers its current head.
5. **Leave the stack alone while it lands.** Watch each PR with `schedule.watch_pr(repo, pr, mode="watch", ...)` until it reads merged, and re-read it when the watch wakes. A base that moves to trunk when its parent merges is expected, not damage to repair. If a merge stalls, find out why before you change anything.
6. **Stop at the ceiling.** Extending the run takes new verdicts, so it is a new pass through step 1.

**Verifier rules.** The bar in the kickoff is the whole bar: add no check, gate, sign-off or review round above it. Block only for a failing run at this head or a bug a user would hit, and report anything the base already has in one line. A self-review runs at most one review round and one fix round. Findings left after that are reported, not acted on, and a fix round is never itself re-reviewed.

**Reply:** the verified run and its ceiling, each PR's verdict and who produced it, what landed and how you confirmed it, and what the next gap needs.
